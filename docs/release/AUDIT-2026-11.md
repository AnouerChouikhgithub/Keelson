# Completion audit, November 2026 — findings kept

`AUDIT-REPORT.md` used to sit at the repository root as a working document. It was
removed from the tree (still in history; it is untracked and git-ignored now) because
a 260-line sprint checklist is not a release artifact. What is still worth keeping is
here: the results that shaped the code, and the gaps the audit opened.

The per-defect table and the verification transcript of the final release live in
[FINAL-RELEASE-READINESS-REPORT.md](FINAL-RELEASE-READINESS-REPORT.md); this file does
not repeat them.

## Results the audit produced, and where they live now

- **A route-wide IDOR test.** The audit found that cross-tenant denial was tested per
  endpoint but never across every identifier route. `backend/tests/Integration/RouteIdorTest.php`
  walks the router and calls each `/api` route with a placeholder identifier as a
  foreign tenant and as nobody. It is still the broadest tenant test in the suite.
- **Test counts are not written into documentation.** They were hard-coded in six
  documents and drifted. `bin/test-counts.sh` runs both suites and prints the counts;
  the documents point at it. Keep it that way.
- **The Windows line-ending artifact.** With `core.autocrlf=true` and no
  `.gitattributes`, `php-cs-fixer --dry-run` flags every file on a Windows checkout
  while CI on Linux is clean. Documented in `AGENTS.md`; the audit's suggestion
  (`* text=auto eol=lf`) was not adopted, so a Linux check remains the reference.
- **The manual browser pass** found the UI reaching the API correctly but could not
  deliver synthetic pointer clicks through the automation panel. Real pointer input is
  covered by the Playwright journeys, which use a real Chromium; treat the manual pass
  as a rendering check, not an interaction test.
